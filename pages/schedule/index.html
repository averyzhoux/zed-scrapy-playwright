zed-sp-schedule

调度器子包：把 Playwright 对象登记成“对象表”，用 CSS 选择器挑选并复用。

v0.1.3dev 导入名 zed_sp_schedule 可选安装

主包默认的 Provider 每次接管请求都会新建一个页面；而调度器子包会预先 创建并管理 Playwright / Browser / BrowserContext / Page 对象，让它们可以被复用。

安装

pip install "zed-scrapy-playwright[schedule]"
# 或
pip install zed-sp-schedule

安装后无需改代码：中间件探测到 zed_sp_schedule 时会自动改用 Scheduler。

开发中 本子包仍在早期开发阶段：对象表、状态与首页装配已经可用， 而基于队列的调度与 takeover 的完整接管逻辑尚在完善。

工作原理

调度器启动时会在一个“首页”里构建如下 DOM，每个被管理的对象对应一个元素； 元素的属性把 DOM 和对象表关联起来： 

<main>
  <playwright>
    <browser>
      <context>
        <page></page>
      </context>
    </browser>
  </playwright>
</main>
属性来源含义
data-address PageData.address 对象表里对应 ObjectProxy 的地址（id()）。
data-status PageData.status 该对象当前的使用状态。

于是爬虫里就能写 selector="page.default" 这样的 CSS 选择器， 由调度器把选择器解析成具体的 Playwright 对象。

页面状态

状态含义调度优先级
Leisure空闲，可直接使用最高
Cooling冷却中次之
BeUsing正在被使用再次
Unmount已卸载最低

API

from zed_sp_schedule import Scheduler, PageStatus, PageData, ObjectProxy

scheduler = await Scheduler(config).start()   # config 同主包 ConfigDict
proxies = await scheduler.css("page.default") # 按选择器取出对象代理
response = await scheduler.takeover(request)  # 接管一个 ZedRequest
await scheduler.close()                       # 释放资源
成员说明
Scheduler(info)调度器主体，继承自主包的 Provider。
Scheduler.start()启动 Playwright、装配首页并登记默认对象；未提供 config 时抛 ValueError。
Scheduler.css(selector)返回选择器命中的 ObjectProxy 列表。
Scheduler.takeover(request)接管请求：无 selector 时新开页面，否则按选择器分发。
Scheduler.close()关闭浏览器并停止 Playwright。
PageStatus页面状态枚举。
PageDataDOM 属性名枚举（data-address / data-status）。
ObjectProxy被调度的对象 + 一个 asyncio.Queue。

默认登记的对象

bind_defaults() 会登记四个默认对象并绑定到对应元素：

选择器对象
playwright:firstself.playwright
browser:firstself.default_browser
context:firstself.default_context
page:firstself.default_page（class 含 default，可用 page.default 选中）

自定义 HTML

首页骨架来自包内 zed.home.html，其中 <main> 会被“自定义配置”替换，用来声明各种页面组合。定位优先级为：

  1. 命令行参数 zed=<path>；
  2. 当前工作目录下的 zed.custom.html；
  3. 包内默认的 assets/zed.custom.html。
找不到文件时 显式通过命令行指定的文件若不存在，check() 会抛出 FileNotFoundError。
